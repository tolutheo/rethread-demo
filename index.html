System prompt + a 2 MB itinerary PDF attached. Both stored once, referenced by hash from here on — the PDF never bloats another event again. Customer name and booking reference tokenized into the PII vault.

History re-sent by the app (that's how LLMs work) — but PDF and prompt already exist, so we store nothing twice. 15 KB flight-search result stored once.

Same tool, same arguments, back to back — flagged loop_suspected automatically. This is the kind of stuck-agent behavior that silently burns tokens and is invisible in raw logs.
